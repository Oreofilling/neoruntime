主媒体面尽量传递 DMA-BUF 文件描述符而非复制像素；服务控制面主要使用 protobuf/gRPC；浏览器边界转换为 JSON、WebSocket、SSE 或 MSE 可消费的二进制帧。

当前零拷贝主线Sensor → ISP → NV12 DMA-BUF → camera-daemon → SCM_RIGHTS → ai-runtime → NPU。生命周期由订阅、FRAME_IN_USE、引用计数、RELEASE 与 watchdog 共同闭环；当前实现不是共享内存环形队列。

3. 事件、状态与审计

运行时 event-bus 是低延迟内存扇出；平台审计日志是另一条可持久化链路。两者语义和可靠性不同。

运行时事件总线（非持久）

发布者ai-runtime · app-manager · device-control · platform-api · apps/plugins
Event protobuf
event-bustopic / timestamp_ns / source / event_id / bytes payload / type / metadata
exact · * · ** · filter
订阅者camera AI overlay · platform-api WebSocket · apps/plugins/CLI
  • UDS /run/aipc/event-bus.sock；C++ 客户端可用 127.0.0.1:50053。
  • 每订阅者有界队列；发布非阻塞，队列满会丢弃并计数。
  • 服务重启后事件消失；当前源码未把配置中的 persist 变成持久队列。

操作 / 审计日志（可持久）

HTTP / 系统操作用户、请求、资源、动作、结果、客户端信息
async batch
EventLogger缓冲、批量写入、失败记录
WAL transaction
platform.db / EventLog查询、筛选、导出、REST 返回
  • 审计日志通过平台 REST 读取，不依赖 event-bus 的存活时间。
  • 配置变更另有 ConfigRevision / ConfigApplyJob 记录。
  • 系统、应用与容器文本日志走 journal/file → API/WS，不等于审计表。

10. 当前实现注意项

这些不是概念图的简化，而是源码核对时发现的真实边界、差异或待复核点。

共享内存链路已不是当前主线

include/shm_protocol.h 被源码标为 unused/dead。原始帧实际通过 camera.sock + SCM_RIGHTS 传 DMA-BUF FD，不能再按旧文档画成 SHM ring。

编码 UDS 头版本需要联调复核

camera EncodedPublisher 当前写 V3 38 字节头；platform-api 的 H264/audio 读取代码只显式处理 V1 22B / V2 30B。额外的 8 字节 packet_seq 可能被误当 payload。

AutoInfer topic 与 StreamInfer 不同

StreamInfer 自动发布为 inference/<model_id>/<stream_id>；独立 AutoInfer 路径当前发布 inference/<stream_id>。订阅者需兼容两种结构。

event-bus 不提供耐久性

当前服务为纯内存有界队列；慢订阅者会 drop，重启无 replay。配置中的 persist 不能等价理解为已落盘。需要可靠审计时使用 platform-api EventLog。

应用模型权限注册尚未闭环

app-manager 当前代码对模型访问权限仅记录日志，向 ai-runtime 注册细粒度应用权限仍是 TODO；部署策略不应假设这一层已强制执行。

Discovery Web 路由尚未接线

platform-api 存在 discovery handler 代码，但当前主程序未完成 dial/route registration；发现能力目前主要通过 device-discovery 本地 gRPC 和 UDP 使用。

PTZ/GPIO 历史说明不代表当前配置

控制接口仍存在，但当前 NE503 配置中 PTZ disabled、GPIO catalog 为空。实际活跃设备控制以 MCU peripheral/lens 链为准。

“clean raw frame”需结合 flags 理解

FD subscriber 路径设计上优先于 encoder/OSD，但各流仍有 bake 行为。消费者必须读取 OVERLAY_BAKED 与 DPM_BAKED，不要只依赖文字注释。
