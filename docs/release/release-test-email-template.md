## 五、注意事项

> 本章节每版逐条核对是否仍适用，失效条目删除、新增坑补入。以下是历史版本沉淀的常驻候选条目：

1. **版本轴**：MCU 固件不在 OS 镜像内，须单独 OTA 升级；OS / SoC 固件 / 应用 / MCU 四条版本轴独立演进。应用安装按 machine、product、OS 版本闭区间和 data schema 契约校验，请勿跨轴混装。
2. **NPU 独占语义**：NPU 服务持有算力时，独立命令行工具直跑会报错 rc=74（设备被占用）——需做 NPU 裸层跑分时先停止 ai-runtime、camera-daemon、hailort_server，跑完恢复；SDK 与服务端路径不受影响。（本版固件起生效）
3. **危险接口**：`GET /device/gpio` 单次调用即导致设备硬复位（已知问题 #46），请勿调用；REST `DELETE /models` 会直接删除模型文件，请改用 SDK 的 `unregister_model`。
4. **模型注册 id 规范**：注册 id 请从模型文件名派生；固定 id 换不同文件会被自愈机制静默指向旧模型。
5. **订阅交付语义**：订阅实际交付帧率 = min(设定 fps, 源流帧率)；按旧版本定标的性能阈值需按此语义核对。
6. **默认关闭项**：【如帧注入 injection.enabled 出厂为 false，涉及测试先开启并重启 camera-daemon，测后恢复】

## 七、升级与回滚

- 应用升级：按 `docs/deployment/DEPLOYMENT.md`；升级前备份位于 `/data/backups/aipc-app/<旧版本>-<时间>/`，本版已完成一次 `deploy.sh --rollback` 演练【证据路径】。
- OS 升级：按 `docs/deployment/os-upgrade.md`；备份位于 `/data/backups/aipc-os-upgrade/<job-id>/`。本版使用【A/B / single-recovery】路径，已完成【成功切换 / 验证失败回滚 / boot-attempt 回滚】演练【证据路径】。
- 兼容性：应用包在 OS 版本区间、machine/product 或 data schema 不匹配时拒绝安装/启动；OS 升级本身不因应用不兼容而被阻断，升级后由服务启动门和 Platform API 救援通道处置。
- MCU：走独立 OTA，仅允许升级到更高版本；已验证升级后不重复刷写及失败保持原固件。主动降级不属于 OTA 能力，救援恢复使用配对 HEX + SWD/STLink【如适用，证据路径】。
