1. 功能概览与入口

「应用安装向导」是 Web 控制台中把 AI 应用（容器）安装到设备的引导流程，弹窗标题为 「应用安装向导」。整个流程共 三个界面：

1选择镜像来源
  • 本地上传（默认）：.neoapp 应用包 / 镜像 tar
  • 注册表镜像：填写镜像地址在线拉取
2配置应用
  • 左侧导航 5 个分区：基础信息 / 资源分配 / 模型 / 权限设置 / 高级配置
  • 「表单 / YAML」双视图
3安装进度
  • 阶段：校验 → 镜像 → 注册 → 完成
  • 支持「后台运行」；失败可返回修改 / 重试

入口

登录 Web 控制台 → 左侧菜单进入「应用管理」页面：

  • 列表视图：页面右上角 ＋ 导入应用 按钮；
  • 卡片视图：点击卡片区域的导入入口。

点击后弹出「应用安装向导」对话框。移动端浏览器下向导为全屏展示，桌面端为居中大弹窗。

三条安装路径

来源适用文件 / 输入配置来源说明
.neoapp 应用包 xxx.neoapp（包内含 app.yaml + 镜像 tar） 以包内 app.yaml 为准，可在向导中微调 服务端自动解出配置与镜像；离线设备推荐此方式
仅镜像 tar .tar / .tar.gz / .tgz（docker save 导出） 由向导表单生成 app.yaml 应用 ID、名称等需在表单中手工填写
注册表镜像 镜像地址，如 docker.io/library/nginx:latest 由向导表单生成 app.yaml 需外网 设备必须能访问镜像仓库

2. 前置条件

  • 设备 Web 控制台可访问并可登录（默认 http://<设备IP>/，账号见提测说明，默认 admin / password）。
  • 应用管理页面可正常打开（依赖 platform-api、app-manager 服务正常）。
  • 本地安装文件准备就绪：.neoapp 包或镜像 tar；单文件上限 2GB。
  • 注册表路径需设备可访问外网（如 docker.io）。
  • 涉及「模型」分区校验时，设备模型列表接口可访问（接口失败时前端会跳过可用性校验，交由后端在安装时兜底拦截）。
  • 设备存储充足（镜像导入 + 应用注册需要磁盘空间，不足会在安装阶段报错）。

3.1 本地上传（默认选中）

  • 上传槽支持点击选择与拖拽，一次一个文件；上传中显示进度条。
  • 文件类型按后缀路由：
    • .neoapp → 应用包：服务端解包，自动填入「配置 + 镜像」两槽，页面显示 已解出 的应用元信息（ID / 名称 / 版本 / 描述），并提示 「已上传 .neoapp 包：以包内 app.yaml 为准，可在下方微调」。
    • .tar / .tar.gz / .tgz → 仅镜像：提示 「仅上传镜像：由下方表单生成配置文件」。
    • 其他后缀 → 直接 toast 报错：「仅支持 .neoapp 应用包或 .tar / .tar.gz / .tgz 镜像」。
  • 上传后再上传一个 .neoapp：整体替换为包内两槽内容（旧的孤立镜像会被清理）。
  • 清除上传：包是「整体清除」两槽；裸镜像只清镜像槽。
  • 未上传任何文件时点「继续」→ toast 「请先上传 .neoapp 应用包或镜像 tar 文件」；上传进行中「继续」不可点。

3.2 注册表镜像

  • 填写「镜像地址 *」，例如 docker.io/library/nginx:latest；支持 @sha256:<64位十六进制> digest 形式。
  • 地址格式校验（前端）：不允许空格、://、以 / 开头结尾、..；各段须为字母/数字/点/下划线/连字符；支持 registry 主机名带端口。不合法时提示 「镜像地址格式不正确，请填写合法的仓库路径，例如 docker.io/library/nginx:latest」。
  • 页面有明确提示：「从注册表拉取镜像需要设备能够访问外网（如 docker.io）；离线设备请改用本地上传」。

3.3 「继续」按钮可用条件

  • 本地上传：至少上传了一个文件（包或镜像），且当前没有文件在上传中。
  • 注册表：镜像地址非空且格式合法。

4. 第二步：配置应用

配置页为单页表单 + 左侧锚点导航（不是逐页向导），五个分区一次配完，安装时统一校验并自动跳到第一个出错分区。右上角可切换「表单 / YAML」两种视图。

4.1 分区一：基础信息

字段必填默认 / 示例说明
应用 ID是my-app 仅字母、数字与 . _ -，不能以符号开头/结尾。.neoapp 包模式下只读（提示：由上传的 app.yaml 决定 — 清单目录与此 ID 绑定，不可修改）。ID 与已安装应用重复时输入框标红并提示 「该应用 ID 已存在；安装时将覆盖现有应用」。
应用名称是My Application自由文本。
版本否1.0.0自由文本，建议 semver。
描述否—自由文本。

注册表 / 仅镜像 tar 路径下，镜像地址也在基础信息中体现并参与安装校验。

4.2 分区二：资源分配

字段默认说明
CPU 限制50%只能输入 0–100 的数字（自动补 %，超范围自动收敛）。
内存限制256Mi下拉选择：128Mi / 256Mi / 512Mi / 1Gi / 2Gi；若清单带预设外的值会并入选项显示。

4.3 分区三：模型

声明应用依赖的模型（对应清单 spec.models）与推理配额。每个别名在运行时以 AIPC_MODEL_<别名> 环境变量注入应用。

  • 「添加依赖」新增一行：别名 + 模型选择。别名规则：字母或下划线开头，仅字母/数字/下划线。
  • 模型选择下拉列出设备已注册模型；选「自定义模型…」可声明镜像内自带、未注册到系统的模型：
    • 自定义时需提供镜像内 AMPK 模型包（.bin）路径；裸 .hef 内置已不再支持（路径不以 .bin 结尾会拦截安装）。
    • 勾选「必需（缺失时安装失败）」后，模型既不在设备上、又没有 .bin 路径时阻止安装；不勾选则仅服务端告警，可安装。
  • 行的状态徽标：系统模型（设备已注册）、自带模型（声明了 .bin 路径）、 缺失 · 必需（必填且缺路径，安装被拦）、未注册 · 可选。
推理配额字段范围 / 默认说明
最大推理 QPS1–1000，默认 10超出范围自动收敛；清空则用后端默认。
最大并发推理数0–100，默认 00 表示不限制并发。
允许动态注册模型默认关允许应用在运行时发现并注册模型。

4.4 分区四：权限设置

配置块形式说明
视频流权限流标签多选（胶囊勾选）列出设备当前视频流（含分辨率/帧率）；无可选流时显示「暂无可用视频流」。
事件权限两个文本框发布主题（例 app/output）、订阅主题（例 camera/*, sensor/#），多个用逗号分隔。
网络模式下拉隔离模式（默认，无网络访问）/ 主机模式（共享主机网络）。主机模式下额外填写「入站端口」（应用对外暴露的端口，逗号分隔，自动过滤非法端口）。
设备控制四个开关灯光控制 / 红外滤光片 / 云台控制 / 镜头控制。

4.5 分区五：高级配置

配置块形式说明
环境变量键值行（可增删）注入容器的 NAME=value。
卷挂载行（可增删）主机路径 + 容器路径 + 只读（RO）勾选。
运行选项开关 + 下拉「开机自启动」开关；重启策略：不重启 / 失败时重启（默认）/ 总是重启。清单带预设外的策略值会按原值显示。

4.6 表单 / YAML 双视图

  • 上传过 app.yaml（.neoapp 包）：YAML 页签为可编辑 Monaco 编辑器，基线是上传文件的原始字节（保留注释与未知字段）。表单改动会实时写入编辑器文本（编辑器聚焦时以用户文本优先）；点「应用」把文本重新上传服务端并回填表单。解析失败显示「YAML 解析失败」且无法离开 YAML 视图。附带「对比原文件」开关与「复制」按钮；状态角标：与表单实时同步 / 有未应用的修改 / 与文件一致。
  • 注册表 / 仅镜像 tar：YAML 页签为只读预览（由表单生成，可复制拿去当 app.yaml 用）。

4.7 清单修改状态横幅（.neoapp 路径）

横幅文案含义
未修改，将按原文件内容原样安装表单/YAML 均未改动，安装时直接用上传的原始文件（字节一致）。
已修改 N 处，安装前将写回清单安装前会把改动的白名单字段 PATCH 回清单文件再安装。
已修改 N 处，但多容器清单不支持向导修改，仍将按原文件原样安装多容器（spec.containers）清单无法用向导表达，修改不会写回。

5. 第三步：安装与进度

5.1 点击「安装」后发生什么

  1. 整表校验：按基础信息 → 模型的顺序跑全部规则，第一个问题以 toast 提示并自动跳转到对应分区（详见第 6 节）。
  2. 重复 ID 确认：应用 ID 已存在时弹系统确认框「App ID "xxx" already exists. Replace the installed app?」，确认后覆盖安装（先移除旧应用再装新应用）；取消则不安装。
  3. 提交安装（按路径自动选择，用户无感知）：
    • .neoapp 未修改 → 直接按原始文件安装；
    • .neoapp 已修改（单容器）→ 先把改动写回清单，再安装；
    • .neoapp 已修改（多容器）→ 提示后将按原文件安装；
    • 注册表 / 仅镜像 tar → 用表单配置 + 镜像地址/已上传 tar 安装。

5.2 进度页

  • 标题「正在安装应用...」，进度条 + 百分比 + 当前阶段：校验 → 镜像 → 注册 → 完成。
  • 过程文案示例：正在准备安装 / 正在校验应用配置 / 正在拉取镜像… 下载 x%（大小）/ 正在导入本地镜像 / 镜像已存在 / 正在注册应用 / 正在保存应用注册信息 / 正在注册权限 / 安装完成。
  • 后台运行：关闭向导回到应用列表，安装任务在服务端继续，列表随后自动刷新。上传的文件会被安装任务继续使用，不会误删。
  • 成功：toast「应用已安装」，向导自动关闭，应用出现在应用列表（可在列表中启动/停止/查看日志）。
  • 失败：显示「安装失败」+ 具体原因（见第 7 节），提供两个按钮：
    • 返回修改：回到配置页，已上传文件与表单内容保留；
    • 重试：原样重跑安装（沿用已上传文件与表单状态）。
取消行为：在来源页/配置页点「取消」会关闭向导并清理已上传文件； 若安装任务已开始（进入过进度页），关闭等价于「后台运行」，文件保留给任务使用。

8. 建议测试场景清单

  • 来源 · 本地上传 .neoapp：上传后显示「已解出」元信息；来源页横幅为 manifest 模式；应用 ID 只读。
  • 来源 · 仅镜像 tar：横幅提示「由下方表单生成配置文件」；表单完整填写后可安装。
  • 来源 · 注册表：合法地址可继续；非法地址（带空格 / :// / 空值）分别触发对应错误提示。
  • 文件类型拦截：上传 .zip/.exe 等收到「仅支持…」toast。
  • 2GB 上限：构造超限文件验证被拒。
  • 必填校验：ID / 名称留空安装，验证 toast + 自动跳转基础信息。
  • 重复 ID 覆盖：安装已存在 ID → 确认框「替换」走覆盖安装、「取消」不安装；输入框红色提示出现。
  • .neoapp 未修改：横幅「未修改…」，安装后清单与原文件一致（注释/未知字段保留）。
  • .neoapp 已修改（单容器）：横幅「已修改 N 处」；安装后改动生效。
  • 多容器清单：编辑后横幅提示仍按原文件安装，改动不生效（预期行为）。
  • YAML 视图：.neoapp 可编辑（改文本→应用→表单回填；制造语法错误→「YAML 解析失败」且无法离开视图）；注册表/tar 路径为只读预览。
  • 模型依赖：选系统模型（绿色「系统模型」徽标）；自定义模型缺 .bin 路径且勾必需 → 安装被拦并跳转模型分区；不勾必需 → 可继续安装；路径填 .hef → 被拦截。
  • 权限与高级：视频流多选、事件主题逗号分隔、主机模式出现入站端口输入、环境变量/卷挂载增删、自启动与重启策略落盘生效。
  • 进度页：阶段与百分比推进；「后台运行」后列表最终出现新应用。
  • 失败重试：断网拉取失败 → 失败页出现；「重试」在恢复网络后成功；「返回修改」保留已上传文件与表单。
  • 取消清理：上传后直接取消，再重开向导，确认不残留上次状态。
  • 安装后联动：安装完成 toast + 列表刷新；应用可启动/停止，勾选自启动的应用重启设备后自动运行。

10. app.yaml 编写校验限制

YAML 的校验分两层：前端编辑器只做语法级检查（能不能解析、能不能被向导表达）， 结构/取值校验全部在服务端（platform/app-manager/manifest/manifest.go 的 ParseManifest，上传、写回、安装三个入口共用同一套规则）。点「应用」即触发服务端全量校验， 校验不过文本不会被接受。

10.1 前端 YAML 视图的限制

  • 必须是可解析的合法 YAML：解析失败显示「YAML 解析失败」，且无法离开 YAML 视图、无法安装。
  • 可编辑范围：只有上传过 app.yaml（.neoapp 包）才是可编辑模式；注册表 / 仅镜像 tar 路径的 YAML 页签为只读预览。
  • 双向同步：表单改动实时写入编辑器文本（编辑器聚焦时以手工输入的文本优先）；注释、未知字段、键顺序都会保留。
  • 多容器清单（含 spec.containers）：可上传安装，但向导修改不写回，按原文件原样安装。

10.3 模型声明（spec.models）的专项规则

  • 别名（map 的键）必须匹配 ^[A-Za-z_][A-Za-z0-9_]*$（运行时会变成 AIPC_MODEL_<别名> 环境变量）。
  • 保留别名 HOST_PREFIX / APP_ID / APP_ROLE / CONTAINER_NAME 禁止使用（避免遮蔽平台注入的环境变量）。
  • 每个映射的 id 必填；path（镜像自带模型）必须是绝对路径、干净路径（不含 ./../冗余分隔符）且以 .bin 结尾（AMPK 模型包）——裸 .hef 内置已不再支持。
  • 同一 model id 被多个别名声明时，path 必须一致。
  • spec.models.<别名>.type 字段已废弃：出现即整体报错，不会静默忽略（迁移期常见坑）。
  • 声明了 required: true 的模型在安装时必须"设备已注册或提供 .bin 路径"二选一，否则安装失败；可选依赖缺失仅告警。
  • spec.models 中的 id 会被自动合并进 permissions.inference.models 授权列表（仅内存合并，不改写文件）。

10.4 多容器清单（spec.containers）的额外规则

  • 必须恰好一个 role: main 容器，其余为 role: sub；role 取值仅这两种。
  • sub 容器不允许携带 permissions。
  • lifecycle.startup_order / shutdown_order 引用的容器名必须存在。
  • 多容器另有 spec.networking.mode：internal / bridge / host。

10.5 表单改动写回（PATCH）的白名单

向导表单对已上传 YAML 的修改只允许写回以下路径，其余路径整单拒绝（错误 Non-patchable fields: …）：

  • 允许：metadata.name / version / description；spec.resources.cpu / memory； spec.autostart；spec.restart_policy；spec.models（仅整表替换，不支持按别名子路径改）； spec.permissions.*（video、inference 的 max_qps / max_concurrent / allow_register_model、events 发布订阅、device 四个开关、network 模式与入站端口）； spec.env；spec.volumes；spec.security.no_new_privileges / readonly_rootfs。
  • 明确拒绝：metadata.id（目录名绑定，改了会孤儿化）、spec.image（必须与上传 tar 的 RepoTag 一致）、 spec.models.<别名>.* 子路径。
  • 写回后重新全量校验，不通过则磁盘文件保持原样（原子写）。

10.6 文件层面的限制

  • 单独上传 app.yaml：仅接受 .yaml / .yml 后缀。
  • .neoapp 包内 app.yaml 上限 4MB；镜像 tar 上限 2GB，且必须是 docker save 导出的归档。
  • 安装期镜像一致性：tar 内镜像的 RepoTag 必须与清单声明的 spec.image 对得上，否则报 「镜像导入后无法验证 app.yaml 中的镜像…」。
